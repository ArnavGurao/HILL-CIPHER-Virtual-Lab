Cryptography through Linear Algebra

The Hill Cipher encrypts a block of letters together rather than replacing each letter independently. A plaintext block is represented as a vector and multiplied by a square key matrix modulo 26.

Encryption C = K × P (mod 26)
Decryption P = K⁻¹ × C (mod 26)
Aa

Alphabet Mapping

Letters are represented as integers so matrix arithmetic can be applied.

A=0 · B=1 · ... · Z=25
▦

Block Processing

A 2×2 key encrypts two letters at a time; a 3×3 key would encrypt three at a time.

%

Modulo 26

Results are reduced modulo 26 so every value stays within the alphabet range 0–25.

K

Key Matrix

The square matrix acts as the secret transformation applied to each plaintext vector.

1929

Hill Cipher introduced

American mathematician Lester S. Hill published the cipher in The American Mathematical Monthly and demonstrated the use of matrix algebra for cryptography.

1970s

Modern block ciphers emerge

Practical cryptography moved toward algorithms that combine substitution, permutation, diffusion, and non-linear operations.

1977

DES standardized

DES became an important standardized symmetric block cipher for practical systems.

2001

AES standardized

AES became the modern NIST symmetric block-encryption standard.

Important historical wording: The Hill Cipher was not directly “replaced” by one specific algorithm. Modern cryptography evolved toward stronger standardized block ciphers such as DES and later AES.

2×2 Key Matrix

K = [ a  b ]
    [ c  d ]

Determinant

det(K) = ad − bc

Invertibility condition

gcd(det(K), 26) = 1

Inverse Matrix

K⁻¹ = det(K)⁻¹ × [  d  −b ]
                    [ −c   a ]  (mod 26)
Why does gcd(det(K), 26) have to equal 1?

Decryption requires the multiplicative inverse of the determinant modulo 26. Such an inverse exists only when the determinant and 26 are relatively prime. If the gcd is not 1, K⁻¹ does not exist modulo 26.

Advantages

  • Encrypts multiple letters at once.
  • Demonstrates diffusion across a block.
  • Connects linear algebra with cryptography.
  • Can be extended to larger square matrices.

Limitations

  • The encryption transformation is linear.
  • Not every matrix is a valid key.
  • Padding may be required.
  • It is unsuitable for modern secure communication.
!

Why can it be compromised?

With enough known plaintext and matching ciphertext, an attacker can construct matrix equations and solve for the unknown key. This known-plaintext weakness is a consequence of the cipher's linear structure.

Known-Plaintext Attack

The Hill Cipher resists simple single-letter frequency analysis because letters are encrypted in blocks. However, its encryption is a linear transformation, which creates a critical weakness.

If an attacker obtains enough corresponding plaintext and ciphertext blocks, those blocks can be arranged into matrices and used to recover the secret key.

If P is invertible modulo 26, multiply both sides by P⁻¹ on the right:

CP⁻¹ = KPP⁻¹

Security Takeaway

The Hill Cipher is vulnerable to known-plaintext attacks because its encryption is a linear transformation. With enough suitable plaintext–ciphertext pairs, an attacker may reconstruct the secret key matrix.

This is why the classical Hill Cipher is valuable for learning cryptographic principles but is not suitable for modern secure communication.

Step-by-Step Encryption Procedure

  1. 1
    Read inputs

    Accept plaintext and a square key matrix. This implementation uses a 2×2 matrix.

  2. 2
    Normalize plaintext

    Convert to uppercase and remove unsupported characters.

  3. 3
    Pad if necessary

    For a 2×2 key, append X when the cleaned text has odd length.

  4. 4
    Convert letters to numbers

    Apply A=0, B=1, ..., Z=25.

  5. 5
    Build plaintext vectors

    Group each pair into P = [p₁, p₂]ᵀ.

  6. 6
    Multiply by key

    For each block, compute K × P.

  7. 7
    Apply modulo 26

    Reduce every resulting element to a value from 0–25.

  8. 8
    Convert back to letters

    Join all encrypted blocks to obtain the ciphertext.

Encryption Algorithm

INPUT: plaintext P, 2×2 key matrix K

1. P ← uppercase letters only
2. IF length(P) is odd:
       P ← P + "X"
3. Map P from letters to values 0..25
4. Split values into 2-element column vectors
5. FOR each vector v:
       c ← (K × v) mod 26
       append c to encrypted values
6. Map encrypted values 0..25 back to A..Z
7. OUTPUT ciphertext

Step-by-Step Decryption Procedure

  1. 1
    Read ciphertext and key

    Use the same key matrix that was used for encryption.

  2. 2
    Calculate determinant

    For K=[[a,b],[c,d]], compute det(K)=ad−bc.

  3. 3
    Test invertibility

    Verify gcd(det(K),26)=1. Stop if the condition fails.

  4. 4
    Find determinant inverse

    Compute det(K)⁻¹ modulo 26.

  5. 5
    Find inverse key matrix

    Compute K⁻¹ modulo 26.

  6. 6
    Convert ciphertext

    Map letters to 0–25 and create column vectors C.

  7. 7
    Recover plaintext vectors

    Compute P = K⁻¹ × C (mod 26).

  8. 8
    Convert values to letters

    Join recovered blocks to obtain the plaintext.

Decryption Algorithm

INPUT: ciphertext C, 2×2 key matrix K

1. d ← det(K)
2. IF gcd(d, 26) ≠ 1:
       OUTPUT "Invalid / non-invertible key"
       STOP
3. dInv ← modularInverse(d, 26)
4. KInv ← inverseMatrix(K, dInv) mod 26
5. Map C from letters to values 0..25
6. Split values into 2-element column vectors
7. FOR each cipher vector c:
       p ← (KInv × c) mod 26
       append p to plaintext values
8. Map plaintext values 0..25 back to A..Z
9. OUTPUT plaintext
